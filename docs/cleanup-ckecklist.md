# B3-1 AWS 리소스 종료 체크리스트

실습 종료 후 과금 대상 리소스를 정리하고 삭제 여부를 확인하기 위한 체크리스트다.

- AWS 리전: 서울 `ap-northeast-2`
- 프로젝트 VPC: `B3-1-VPC`
- 작성자: ____________________
- 정리 일시: ____________________

> **삭제 전 확인:** 외부 접속, `/health`, Docker 컨테이너 실행 상태 등 제출에 필요한 증빙을 먼저 저장한다. 리소스 삭제 후에는 서비스와 로그를 복구하기 어려울 수 있다. 계정의 다른 프로젝트 리소스와 혼동하지 않도록 리전과 리소스 이름을 확인한다.

## 1. 증빙 저장

- [x] 아키텍처 다이어그램과 문서를 저장했다.
- [x] 외부에서 접속한 결과(브라우저 또는 `/health` 응답)를 저장했다.
- [x] 컨테이너 실행 상태(`docker ps`)와 필요한 트러블슈팅 기록을 저장했다.
- [x] 삭제 전 EC2, VPC, 서브넷, 보안 그룹 등 리소스 목록을 기록하거나 캡처했다.
- [x] 캡처에 키 페어 파일 내용, 비밀번호, 액세스 키 등 비밀 정보가 포함되지 않았는지 확인했다.

## 2. EC2 종료

- [x] 대상 인스턴스가 B3-1 실습용인지 확인했다.
- [x] 인스턴스를 **중지(Stop)가 아닌 종료(Terminate)** 했다.
- [x] EC2 콘솔에서 인스턴스 상태가 `terminated`인지 확인했다.
- [x] 인스턴스 종료 후 남은 네트워크 인터페이스(ENI)가 있는지 확인하고, 실습용 미사용 ENI만 삭제했다.

> 인스턴스를 중지만 하면 EBS 볼륨이 남아 과금될 수 있다. 실습을 완전히 끝낼 때는 종료 상태까지 확인한다.

## 3. 스토리지 및 공인 IP

- [x] EC2 종료 후 EBS 볼륨 목록을 확인했다.
- [x] 실습용 미사용 EBS 볼륨이 남아 있으면 삭제했다. 루트 볼륨도 종료 시 자동 삭제되지 않았는지 확인했다.
- [x] 실습 중 생성한 스냅샷이 있다면 필요한 보존 여부를 결정하고, 불필요한 스냅샷을 삭제했다.
- [x] Elastic IP를 별도로 할당했다면 연결을 해제하고 **Release** 했다.
- [x] Elastic IP 목록에 실습용 주소가 남지 않았음을 확인했다.

> EC2에 자동 할당된 퍼블릭 IPv4 주소는 Elastic IP와 다르다. 인스턴스 종료 시 자동으로 반환되므로 별도 Release 대상이 아니다. Elastic IP를 따로 할당한 경우에만 Release 여부를 확인한다.

## 4. 선택 생성 리소스 확인

아래 리소스는 실습에서 만들었을 때만 정리한다. 만들지 않은 항목은 콘솔에서 존재하지 않음을 확인하고 완료로 표시한다.

- [x] NAT Gateway를 삭제했거나, 생성하지 않았음을 확인했다.
- [x] ELB/ALB를 삭제했거나, 생성하지 않았음을 확인했다.
- [x] RDS 인스턴스를 삭제했거나, 생성하지 않았음을 확인했다.
- [x] 위 리소스에 연결된 Elastic IP, 스냅샷, 백업 등 별도 보존 리소스를 확인했다.

## 5. 네트워크 리소스 삭제

EC2와 연결된 리소스를 먼저 정리한 뒤, 다음 순서로 네트워크 리소스를 삭제한다.

- [x] 실습용 보안 그룹 `B3-1-Web-SG`를 사용하는 ENI나 리소스가 없는지 확인하고 삭제했다.
- [x] 사용자 지정 라우팅 테이블이 서브넷에 연결되어 있다면 연결을 해제했다.
- [x] 사용자 지정 라우팅 테이블을 삭제했다. 기본(Main) 라우팅 테이블은 VPC에 속하므로 직접 삭제하지 않는다.
- [x] 퍼블릭 서브넷 `B3-1-Public-Subnet`을 삭제했다.
- [x] Internet Gateway를 VPC에서 **분리(Detach)** 한 다음 삭제했다.
- [x] VPC `B3-1-VPC`를 삭제했다.
- [x] VPC 콘솔에서 실습용 VPC와 관련 서브넷, Internet Gateway가 남지 않았음을 확인했다.

## 6. IAM 및 실습 보조 항목

IAM 리소스와 키 페어는 보통 EC2/VPC 과금 항목은 아니지만, 실습 전용으로 만든 경우 권한과 보관 상태를 정리한다.

- [x] 실습 전용 IAM 사용자 또는 그룹을 다른 용도로 사용하지 않는지 확인했다.
- [x] 전용 계정을 더 이상 사용하지 않는 경우, 실습용 그룹의 권한을 제거하고 사용자/그룹을 삭제했다.
- [x] 재사용할 IAM 사용자, MFA 설정, 다른 프로젝트 권한은 삭제하지 않았다.
- [x] 실습 전용 EC2 키 페어를 더 이상 사용하지 않는 경우 AWS의 키 페어 등록 항목을 삭제했다.
- [x] 로컬 개인 키 파일(`.pem`)을 보존할지 결정했다. 보존한다면 안전한 위치에 보관하고 공개 저장소에 올리지 않았다.

## 7. 최종 확인 및 증빙

- [x] 서울 리전에서 실행 중이거나 종료되지 않은 실습용 EC2 인스턴스가 없다.
- [x] 실습용 EBS 볼륨과 불필요한 스냅샷이 남지 않았다.
- [x] 실습용 Elastic IP가 할당 상태로 남지 않았다.
- [x] NAT Gateway, ELB/ALB, RDS를 생성했다면 모두 삭제되었다.
- [x] `B3-1-VPC`, 실습용 서브넷, Internet Gateway, 사용자 지정 라우팅 테이블, 보안 그룹이 정리되었다.
- [x] Billing Dashboard 또는 Cost Explorer에서 비용과 남은 리소스를 확인했다.
- [x] 삭제 완료 화면 또는 리소스 목록을 제출용 증빙으로 저장했다.

> Billing Dashboard 반영에는 시간이 걸릴 수 있다. 리소스가 삭제된 직후에도 사용량과 비용이 표시될 수 있으므로, 리소스 목록의 삭제 상태를 먼저 확인하고 이후 비용 화면도 다시 확인한다.
