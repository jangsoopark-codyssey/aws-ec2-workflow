# Subnet

## 개요

서브넷은 네트워크를 나눈 IP 주소 범위이다. AWS에서는 VPC의 주소 범위 일부를 서브넷으로 정의하고 그 안에 EC2 등의 리소스를 배치한다.

## 역할과 동작 방식

AWS 서브넷 하나는 하나의 AZ에만 속한다. 여러 AZ에 배치하려면 각각 서브넷을 만들어야 한다. 같은 VPC의 서브넷 주소 범위는 겹치지 않아야 한다.

예를 들어 `10.0.0.0/16` VPC의 `10.0.1.0/24` 서브넷에는 IPv4 주소 256개가 포함된다. 일반적인 AWS IPv4 서브넷은 처음 네 개와 마지막 한 개의 주소를 예약하므로 이 예에서 리소스에 할당 가능한 주소는 251개이다.

## AWS에서의 사용

| 구분 | 경로의 특징 |
|:---|:---|
| Public subnet | 연결된 라우팅 테이블에 인터넷 게이트웨이로 직접 가는 경로가 있음 |
| Private subnet | 인터넷 게이트웨이로 직접 가는 경로가 없음 |

프라이빗 서브넷도 NAT Gateway 등을 통해 외부로 연결을 시작할 수 있다. 퍼블릭 여부는 서브넷 이름이나 공인 IP 자동 할당 설정만으로 판단하지 않는다.

## 주의사항

퍼블릭 서브넷에 있어도 EC2가 사설 IPv4만 가지고 있으면 IPv4 인터넷에서 직접 접속할 수 없다. 서브넷 경로와 개별 인스턴스의 주소 및 보안 설정을 함께 확인한다. Network ACL은 상태를 추적하지 않으므로 사용자 지정 규칙에서는 응답 트래픽의 포트 범위도 고려해야 한다.
