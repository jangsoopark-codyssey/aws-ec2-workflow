# Writing and Formatting

- Write explanations in Korean unless the surrounding document is English. Keep AWS service names and standard technical terms in English where useful.
- Use Markdown ATX headings with a space after `#`. Keep paragraphs short and use tables for glossary entries.
- Preserve English glossary terms, Korean explanations, existing column conventions, and `-` where an abbreviation is unavailable.
- Use lowercase, hyphen-separated filenames and relative links. Check that linked paths exist.
- Use explicit placeholders such as `<public-ip>` and `<your-ip>/32`; label examples as examples.
- Separate required outcomes from optional extensions. Do not claim an unverified state as fact.
- Never include access keys, passwords, private keys, session tokens, or unnecessary account details.
